# Координатор

Хранит отдельно инвентарь мест, назначения преподавателей и журнал операций. Потеря heartbeat меняет состояние узла. Изменение инвентаря требует административной операции. Координатор получает identity из аутентифицированного соединения. При каждом открытии просмотра, включении управления и выполнении действия заново разрешает nodeId через текущие место и аудиторию. При изменении назначений отзывает подписки и разрешения.

Потоки миниатюр ограничивать по числу подписчиков и видимых мест. Для каждого выхода хранить в памяти последний кадр активной сессии и метку проверки. Удалять при выходе, отзыве доступа и истечении политики хранения. В журнал писать запрос и исход по каждой цели. Последовательность запуска описана в [архитектуре](../docs/architecture.md).

## Локальная приёмка T02

Симулятор T02 использует Python 3.12, SQLite из стандартной библиотеки и валидатор общей схемы из окружения проверки репозитория. Это обратимый выбор для локального стенда. Для эксплуатационного координатора в архитектуре выбран Go. Инвентарь записывается в SQLite при первом запуске. Состояние соединений хранится в памяти, после перезапуска узлы начинают с offline.

Из корня репозитория в активированном окружении запустите:

```sh
python server/acceptance.py
python3 checks/verify.py
```

Первый сценарий сам создаёт временную БД, запускает два процесса по очереди и проверяет ответы по HTTP. После login видны два выхода. Через 1,2 с без подтверждения захвата heartbeat оставляет узел online с превью stale. После 4,1 с тишины сессия очищена. После рестарта без файла начальных данных аудитория совпадает целиком, включая координаты мест.

Для ручной работы запустите в первом терминале:

```sh
python server/coordinator.py --db /tmp/classctl-t02.sqlite
```

Во втором терминале из корня репозитория:

```sh
base=http://127.0.0.1:8765
curl "$base/room"
curl --json @contracts/examples/status.json "$base/nodes/pc-01/status"
curl --json @contracts/examples/capabilities.json "$base/nodes/pc-01/capabilities"
sleep 3
curl --json '{}' "$base/nodes/pc-01/heartbeat"
sleep 7
curl "$base/nodes/pc-01/status"
```

По умолчанию пороги свежести и связи равны 2 и 6 секундам. Снимок status моделирует сводное подтверждение двух выходов от фиктивного источника. Координатор отсчитывает срок по монотонным часам при получении события. Слушатель привязан к IPv4 loopback, обработчики просмотра, ввода и исполнения действий отсутствуют.
