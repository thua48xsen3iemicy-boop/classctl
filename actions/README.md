# Доверенные действия

[Объявление узла](../contracts/examples/capabilities.json) связывает устойчивый actionId с названием, правом, пользовательским или системным контекстом, пределом TTL и идентификатором схемы параметров. Puppet устанавливает проверенные пакеты и доступный только администратору реестр соответствий ID → реализация → схема. Браузер передаёт ID и данные. Сервер и исполнитель сверяют их со своим доверенным реестром, текущими правами и возможностями. Исключить произвольное выполнение команд, загрузку кода и выбор исполняемого файла из запроса.

1. Координатор раскрывает выбор места, группы или аудитории в неизменный список nodeIds. Каждой цели назначает исход. Для отключённого узла сразу возвращает rejected/offline. Пользовательская операция привязывается к текущей сессии при допуске. При смене сессии допуск аннулируется.
2. Обе стороны проверяют issuedAt ≤ текущее время < expiresAt и TTL в пределах maxTtlSeconds. Требуется синхронизация часов, при недостоверном времени отклонить опасное действие. Просроченная команда получает expired. После reconnect отключение и перезагрузку автоматически не повторять.
3. Перед побочным эффектом исполнитель транзакционно резервирует ключ (requestId,nodeId) в устойчивом журнале с отпечатком параметров, действия и срока. Параллельная или повторная доставка того же запроса возвращает сохранённое состояние. Изменённый запрос с тем же ключом получает rejected/conflict. После сбоя между запуском и фиксацией результата вернуть unknown. Хранить записи как минимум до истечения срока с запасом на расхождение часов.
4. accepted означает принятие, succeeded требует подтверждения обработчика, failed фиксирует известную ошибку. Потеря узла после принятия выключения даёт unknown, если подтверждения нет. Снимок результата сохраняет все цели, пока принимаются отдельные ответы. Оператор видит возможную неопределённость и журнал.

**Безопасный пример.** [demo.echo](demo.echo/demo.py) принимает метку по [схеме](demo.echo/parameters.schema.json) и возвращает её вызывающему процессу. [Проверка](../checks/verify.py) запускает его с параметрами примера и отдельно проверяет отказ на лишнем поле. Контекст system в объявлении указывает маршрут будущей доставки. Для исполнения примера достаточно обычного пользователя.

**Будущие плагины.** Выключение и перезагрузка требуют системного права и короткого срока. Открытие ссылки выполняется в текущей пользовательской сессии с проверкой схемы URL и разрешённых адресов. Политика ограничения интернета на физическом ПК сохраняет управляющий канал, DNS и необходимые учебные сервисы по явно заданному списку. Перед применением проверить маршрут к координатору, предусмотреть локальный откат по таймеру. Браузер внутри xrdp открывает соединения на терминальном сервере. Для ограничения его трафика требуется отдельная серверная политика с привязкой к пользователю. Проверить оба пути раздельно на стенде.
