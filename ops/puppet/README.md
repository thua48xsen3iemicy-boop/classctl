# Обновления classctl через Puppet

Для уже работающего кабинета достаточно назначить две роли. На следующем применении каталога каждая машина сама проверит ветку Git и установит её текущую ревизию. Преподавателю не нужно включать весь класс для обновления.

## Подключение к существующему Puppet

1. Скопируйте каталог [classctl](classctl) в `modules/classctl` своего Puppet environment. Это локальный код проекта. Все ресурсы входят в Puppet, зависимостей из Forge нет.
2. Добавьте объявления ролей в свой `site.pp` или в существующий классификатор. Замените имена машин и адрес координатора на свои.

```puppet
node 'teacher-01.school.lan' {
  include classctl::teacher
}

node /^pc-\d+\.school\.lan$/ {
  class { 'classctl::student':
    coordinator => 'https://classctl.school.lan:8767',
  }
}
```

Ученическая роль берёт `node_id` из короткого имени хоста. Если в существующем инвентаре другое имя, задайте `node_id => 'pc-01'` явно. Адрес координатора должен совпадать с DNS/IP в его сертификате. У учительской роли параметры `port` и `ui_port` по умолчанию равны 8767 и 8768.

3. Оставьте включённым штатный периодический запуск Puppet agent. Обе роли по умолчанию следят за `main` в GitHub-репозитории classctl. Для локального зеркала укажите `repository` и при необходимости `branch` в объявлениях обеих ролей. Агентам нужен доступ на чтение Git без интерактивного ввода. Период проверки определяется настройкой Puppet `runinterval`.

## Кабинет после deploy.py

Сохраните текущие `/etc/classctl` и `/var/lib/classctl` на машинах и CA аудитории у администратора. При настройках выше роли используют уже установленные сертификаты, комнату и права. Порты и идентификаторы возьмите из прежнего JSON. Для обновления кода запускать deploy.py больше не требуется. Назначайте машине только одну роль и один способ установки.

Учительская роль обновляет инвентарь в существующей SQLite, запускает службу и проверяет локальный портал. Ученическая роль обновляет системную службу и KDE-автозапуск. Смена ревизии использует тот же механизм обновления работающего графического агента, что и SSH-установка. OpenRC и systemd выбираются на месте. Нужны Git, OpenSSL, Python с venv и pip, системные зависимости роли из [инструкции установки](../ssh/README.md). Настройки зеркала или прокси pip задайте для системного pip на машинах. Окружение Python переиспользуется при неизменных зависимостях.

## Проверка сертификатов перед обновлением

Обе роли рассчитаны на машины с заранее установленными учётными данными classctl. На учительском ПК каталог сертификатов — `/etc/classctl/server`, на ученическом — `/etc/classctl/node`. При каждом прогоне, до обращения к Git, агент проверяет наличие `ca.pem`, `cert.pem` и `key.pem`, цепочку доверия, срок действия, пригодность сертификата для роли TLS и соответствие закрытому ключу. При ошибке Puppet сообщает причину и прерывает обновление на этой машине. После исправления сертификатов следующий прогон повторяет проверку.

Выдачу сертификатов и привязку SHA-256 отпечатков ученических сертификатов к `node_id` выполните при первичной подготовке кабинета. На учительском ПК также нужны `/etc/classctl/room.json` и `/etc/classctl/policy.json`. Если эти два файла ведутся в Puppet, можно указать у учительской роли `public_source => 'puppet:///modules/classctl/lab-a/teacher'` и положить их в `modules/classctl/files/lab-a/teacher/`.

## Проверка обновления

1. На пилотных учительском и ученическом ПК выполните `puppet agent -t`. Проверьте портал по адресу `http://127.0.0.1:8768/` на учительском ПК, вход ученика в KDE и миниатюры места. Первый элемент в `/var/lib/classctl/puppet-server.json` или `puppet-student.json` содержит установленный коммит.
2. Повторите `puppet agent -t`. При тех же ревизии, сертификатах и параметрах установка пропускается, служба продолжает работать. Остановленную службу Puppet запускает снова.
3. Выключите ученический ПК и обновите ветку. Проверьте новую ревизию на учительском ПК. Включите ученика и дождитесь запуска его агента. Сверьте ревизии и состояние места в портале.
4. При недоступном Git или неудачной установке Puppet сообщит об ошибке и повторит попытку при следующем применении. Отметка успешной установки записывается после активации роли. Для возврата к предыдущему коду опубликуйте revert в отслеживаемой ветке.
