# Просмотр одного места

Веха обслуживает первое место из инвентаря координатора. В гриде преподаватель видит выходы XRandR. Кнопки открывают монитор или весь рабочий стол в режиме просмотра. Возврат закрывает PeerConnection и восстанавливает подписки грида. Команды ввода отсутствуют.

## Воспроизведение на одном хосте

Нужны Linux, Python 3.12, Chromium, OpenSSL. Для браузера с ограничением прямого UDP установите coturn с командой turnserver. В активированном окружении из корня репозитория:

```sh
python -m pip install -r ops/requirements-live.txt playwright==1.62.0
python server/live_acceptance.py
python server/acceptance.py
python server/access_acceptance.py
python3 checks/verify.py
```

Первая команда проверки запускает временные CA, координатор, узел, синтетический источник и Chromium. Тест сверяет размеры видео с геометрией выбранного монитора и всего стола, выводит выбранный ICE-кандидат, возвращается в грид, перезапускает сессию и отзывает право во время просмотра. Временные ключи удаляются. На двух активных выходах можно выполнить тот же сценарий под пользователем графической сессии командой `python server/live_acceptance.py --x11`. Она захватывает видимый рабочий стол для локального тестового браузера.

## Подготовка физического места

Установите зависимости из ops/requirements-live.txt на сервере и ученическом ПК. На Calculate нужны Xorg, xrandr, сборка Pillow с XCB, busctl и работающий интерфейс org.freedesktop.login1 (elogind). Для пилота оператор выбирает один UID на seat0. Отдельные каталоги конфигурации и закрытых ключей службы должны принадлежать службе. X11-процесс использует сокет в защищённом от записи пользователем каталоге. Ключ узла остаётся у службы.

Выпустите серверный сертификат с DNS-именем координатора в SAN и клиентские сертификаты узла и преподавателя с назначением TLS client authentication. Доставьте доверенный CA на узел и в браузер, импортируйте в браузер клиентский сертификат преподавателя с ключом. В policy.json используйте формат [T06](../server/README.md). Назначьте сертификату преподавателя view на lab-a, сертификату узла — pc-01. Инвентарь при первом запуске берётся из [примера аудитории](../contracts/examples/room.json). Политика перечитывается во время сеанса.

Запустите из корня установленного репозитория. Имена хостов, пути, UID и адрес привязки замените значениями своего стенда.

```sh
# Координатор в LAN
python server/live.py --host 192.168.1.10 --port 8767 \
  --db /var/lib/classctl/room.sqlite --policy /etc/classctl/policy.json \
  --ca /etc/classctl/ca.pem --cert /etc/classctl/server.pem --key /etc/classctl/server.key

# Системная служба на ученическом ПК, каталог /run/classctl принадлежит службе
python node/live.py --server https://classctl.school.lan:8767 --node pc-01 \
  --socket /run/classctl/seat0.sock --uid 1000 \
  --ca /etc/classctl/ca.pem --cert /etc/classctl/node.pem --key /etc/classctl/node.key

# Автозапуск KDE от пользователя на физическом месте с его DISPLAY и XAUTHORITY
python session/live.py --socket /run/classctl/seat0.sock --node pc-01
```

Службе нужны права назначить владельца сокета выбранному UID. При каждом локальном подключении сверяются UID и PID из SO_PEERCRED, активность, тип, seat и локальность сессии по login1. Смена активного места закрывает сокет. Параметр --test-session предназначен для временного loopback-стенда с UID запустившего процесс. Поставка пакета, OpenRC и автоматическое назначение учётных записей остаются задачей эксплуатации.

В браузере открыть HTTPS-адрес координатора на порту 8767. Браузер и узел используют mTLS/WSS. Служба поддерживает исходящее соединение и объявляет online до входа пользователя. Подписка или WebRTC-запрос проходят проверку T06. Координатор выдаёт билет непосредственно в привязанный канал узла и повторно проверяет полномочия при погашении. Для источника действует локальная аренда 3 секунды, координатор продлевает её при сохранении прав. При пропадании связи процесс закрывает треки. Для первого места JPEG-подписка использует отдельный WSS на выход, ACK от браузера ограничивает число кадров в пути. Источник берёт свежий кадр после ACK. Это упрощение сквозной вехи; нагрузочное сравнение очередей и объединение подписок остаются для T09.

SDP передаётся через координатор, WebRTC выбирает ICE-маршрут. Если прямой маршрут недоступен, передайте координатору --ice /etc/classctl/ice.json с массивом RTCIceServer для браузера (urls, username, credential локального TURN). У браузера должен быть маршрут к TURN, у TURN — к UDP-кандидату узла. Используйте ограниченные по времени учётные данные и сетевую политику учреждения.

## Приёмка

1. До логина проверить online и отсутствие графической сессии. После входа сверить оба выхода с xrandr --query.
2. Открыть окно xrdp на первом выходе, изменяющийся документ на втором. Сверить изображения, выбрать второй крупно, затем весь стол. Проверить неподвижную страницу и возобновление изменений. Вернуться в грид.
3. Повернуть физический выход, переключить зеркало и отключить один монитор. Старые кадры и трек должны очиститься, новые подписки использовать новую ревизию. После logout карточка остаётся, изображения исчезают. После нового входа видны кадры новой сессии.
4. Удалить право преподавателя в policy.json во время просмотра. Проверить исчезновение видео и журнал SQLite audit. Восстановить право и открыть новый просмотр. Записать тип выбранной ICE-пары в диагностике WebRTC браузера.

В облачной проверке использовались синтетический источник и отдельный Debian Xorg с драйвером dummy и двумя виртуальными выходами. На Xorg проверены захват через XCB, второй выход, весь стол, зеркало, отключение выхода, отзыв и возврат в грид. Выбранный маршрут Chromium — relay через локальный TURN/TCP. Физические поворот, KDE/logout, xrdp, привязку сессии через elogind на Calculate и прямой LAN ICE следует подтвердить на классе.
