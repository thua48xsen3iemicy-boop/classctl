# Просмотр одного места

В гриде помещаются все закреплённые рабочие места аудитории. Щелчок по миниатюре открывает выбранный монитор в той же вкладке. Для преподавателя с правом control это сразу включает управление. При праве view открывается просмотр. Щелчок запрашивает полноэкранный режим. При запрете браузера видео занимает всю вкладку. Наведите курсор на стрелку справа или коснитесь её и выберите «← В аудиторию». Esc также закрывает соединение и возвращает карточки на прежние места.

## Воспроизведение на одном хосте

Нужны Linux, Python 3.12, Chromium, OpenSSL. Для браузера с ограничением прямого UDP установите coturn с командой turnserver. В активированном окружении из корня репозитория:

```sh
python -m pip install -r ops/requirements-live.txt playwright==1.62.0
python server/live_acceptance.py
python server/acceptance.py
python server/access_acceptance.py
python3 checks/verify.py
```

Первая команда проверки запускает временные CA, координатор, узел, синтетический источник и Chromium. Тест сверяет размеры видео с геометрией каждого выбранного монитора, выводит выбранный ICE-кандидат, возвращается в грид, перезапускает сессию и отзывает право во время просмотра. Временные ключи удаляются. На двух активных выходах можно выполнить тот же сценарий под пользователем графической сессии командой `python server/live_acceptance.py --x11`. Она захватывает видимый рабочий стол для локального тестового браузера.

## Подготовка физического места

Установите зависимости из ops/requirements-live.txt на сервере и ученическом ПК. На Calculate нужны Xorg, xrandr, сборка Pillow с XCB, busctl и работающий интерфейс org.freedesktop.login1 (elogind). Отдельные каталоги конфигурации и закрытых ключей службы должны принадлежать службе. X11-процесс использует сокет в защищённом от записи пользователем каталоге. Ключ узла остаётся у службы.

На выделенном учительском ПК запустите один координатор для кабинета. Выпустите серверный сертификат с DNS-именем координатора в SAN и клиентский сертификат каждого агента с назначением TLS client authentication. Доставьте агентам доверенный CA. Браузер открывает локальный HTTP и не требует импорта сертификатов.

В `policy.json` сохраните раздел `nodes` из [T06](../server/README.md), где отпечаток сертификата агента сопоставлен с `nodeId`. Перенесите права кабинета с отпечатка преподавателя в запись `"teachers":{"local":{"rooms":{"lab-a":["view"]}}}`. Инвентарь при первом запуске берётся из [примера аудитории](../contracts/examples/room.json). Политика перечитывается во время сеанса.

Запустите из корня установленного репозитория. Имена хостов, пути, UID и адрес привязки замените значениями своего стенда.

```sh
# Координатор на учительском ПК
python server/live.py --host 192.168.1.10 --port 8767 --ui-port 8768 \
  --db /var/lib/classctl/room.sqlite --policy /etc/classctl/policy.json \
  --ca /etc/classctl/ca.pem --cert /etc/classctl/server.pem --key /etc/classctl/server.key

# Системная служба на ученическом ПК, каталог /run/classctl принадлежит службе
python node/live.py --server https://classctl.school.lan:8767 --node pc-01 \
  --socket /run/classctl/seat0.sock \
  --ca /etc/classctl/ca.pem --cert /etc/classctl/node.pem --key /etc/classctl/node.key

# Автозапуск KDE от пользователя на физическом месте с его DISPLAY и XAUTHORITY
python session/live.py --socket /run/classctl/seat0.sock --node pc-01
```

При каждом локальном подключении служба сверяет UID и PID из SO_PEERCRED с обычной активной локальной X11-сессией seat0 по login1. При смене сессии служба закрывает прежнее соединение. Для установки со сменяемыми пользователями используйте [развёртывание по SSH](ssh/README.md). Параметр --uid позволяет вручную ограничить сокет одним пользователем и обязателен для временного loopback-стенда с --test-session.

В браузере учительского ПК откройте `http://127.0.0.1:8768/`. Порт 8767 обслуживает только агентов по mTLS/WSS. Служба поддерживает исходящее соединение и объявляет online до входа пользователя. Подписка или WebRTC-запрос проходят проверки прав кабинета, цели и текущей сессии. Координатор выдаёт билет непосредственно в привязанный канал узла и повторно проверяет полномочия при погашении. Для источника действует локальная аренда 3 секунды, координатор продлевает её при сохранении прав. При пропадании связи процесс закрывает треки. Для первого места JPEG-подписка использует отдельный WebSocket на выход, ACK от браузера ограничивает число кадров в пути. Источник берёт свежий кадр после ACK. Нагрузочное сравнение очередей и объединение подписок остаются для T09.

Миниатюры вписываются в 800×450 с сохранением пропорций. Качество JPEG равно 80. Минимальный интервал между циклами захвата составляет 500 мс и задаёт верхний предел 2 кадра/с на выход. При неизменном изображении источник отправляет подтверждение свежести кадра.

SDP передаётся через координатор, WebRTC выбирает ICE-маршрут. Если прямой маршрут недоступен, передайте координатору --ice /etc/classctl/ice.json с массивом RTCIceServer для браузера (urls, username, credential локального TURN). У браузера должен быть маршрут к TURN, у TURN — к UDP-кандидату узла. Используйте ограниченные по времени учётные данные и сетевую политику учреждения.

Для крупного просмотра узел захватывает до 15 кадров/с в исходном разрешении. В локальной сети VP8 начинает с целевого битрейта 4 Мбит/с и адаптирует его в пределах 2–8 Мбит/с. Фактический трафик зависит от содержимого экрана. Для визуальной проверки сравните читаемость одного терминала после остановки прокрутки и во время движения при одинаковом масштабе окна. Если нужно уточнить причину размытия, откройте `chrome://webrtc-internals` перед запуском просмотра и проверьте выбранную ICE-пару и статистику `inbound-rtp`. Сравните протокол, разрешение, потери пакетов и частоту кадров при просмотре с учительского ПК и с рабочего места администратора. SSH-проброс HTTP-порта портала переносит интерфейс и сигнализацию. Медиапоток идёт по маршруту ICE, выбранному браузером.

## Приёмка

1. До логина проверить online и отсутствие графической сессии. После входа сверить оба выхода с xrandr --query.
2. Открыть окно xrdp на первом выходе, изменяющийся документ на втором. Сверить изображения, щелчком открыть второй монитор крупно. Проверить неподвижную страницу и возобновление изменений. Вернуться в грид.
3. Повернуть физический выход, переключить зеркало и отключить один монитор. Старые кадры и трек должны очиститься, новые подписки использовать новую ревизию. После logout карточка остаётся, изображения исчезают. После нового входа видны кадры новой сессии.
4. Удалить право `teachers.local` в policy.json во время просмотра. Проверить исчезновение видео и субъект `local` в журнале SQLite audit. Восстановить право и открыть новый просмотр. Записать тип выбранной ICE-пары в диагностике WebRTC браузера.
5. С ученического ПК проверить доступность порта агентов и недоступность порта UI на LAN-адресе учительского ПК.

В облачной проверке использовались синтетический источник и отдельный Debian Xorg с драйвером dummy и двумя виртуальными выходами. На Xorg проверены захват через XCB, второй выход, весь стол, зеркало, отключение выхода, отзыв и возврат в грид. Выбранный маршрут Chromium — relay через локальный TURN/TCP. Физические поворот, KDE/logout, xrdp, привязку сессии через elogind на Calculate и прямой LAN ICE следует подтвердить на классе.

## T07. Включение управления

Обновите репозиторий и выполните `.venv/bin/pip install -r ops/requirements-live.txt` на узле и координаторе. На ученическом ПК нужны XTEST и xkbcomp. Перезапустите координатор и процесс session/live.py. В записи `teachers.local` файла policy.json задайте `"rooms":{"lab-a":["view","control"]}`. Перезагрузите страницу браузера.

Щёлкните по нужному монитору. Дождитесь видео и надписи «Управление включено». Клавиатура направляется в сфокусированное видео. Для компьютера с двумя мониторами кнопка «Другой монитор» в левой панели переключает экран. Для завершения нажмите Esc или выберите «← В аудиторию» в той же панели. Сеанс контролирует один преподаватель. Ввод обрабатывает процесс текущего пользователя. Координатор связывает события с авторизованным каналом и не записывает клавиши в аудит. [Контракт ввода](../contracts/input.md)

На Calculate проверьте центр и углы обоих мониторов, поля вокруг видео, поворот и зеркало, текущие группы RU/EN, Ctrl+C, удержание Shift и отключение сети. На локальном Xorg тест с --x11 --dummy-layout рассчитан на специально созданный стенд с DUMMY0/DUMMY1; он меняет экранные режимы и временно переключает раскладки. Проверка наблюдает результат ввода непосредственно на X-сервере. При потере ping от браузера действует локальный таймаут 3 секунды плюс один проход цикла очистки.

В гриде Ctrl + колесо изменяет размер карточек. При увеличении карточки переносятся на следующие строки, грид остаётся в пределах ширины окна. Ctrl + 0 возвращает исходный масштаб. В заголовке карточки видны идентификатор компьютера из инвентаря и полное имя пользователя. Процесс `session/live.py` получает поле GECOS по UID через NSS на ученическом ПК. На клиенте FreeIPA запись обычно возвращает SSSD. При пустом GECOS, на старой версии процесса сессии и после выхода пользователя в заголовке остаётся идентификатор компьютера. Для проверки на ученическом ПК выполните `getent passwd <логин>` и сравните имя в пятом поле с подписью в портале.

Если имя не помещается в карточке, оно сокращается многоточием. Полное имя видно при наведении на заголовок. Первый запуск после перехода на новый SSH-автозапуск происходит при следующем входе в KDE. [Обновление работающего агента](ssh/README.md)

В режиме управления вертикальное колесо над видео прокручивает окно под указателем на ученическом ПК. После обновления координатора и агента откройте просмотр для управления. Для проверки наведите указатель на терминал и прокрутите вывод вверх и вниз.

## T15. Выключение и перезагрузка

Обновите координатор и системные службы ученических ПК. При ручной установке запускайте службу узла от root с `--power-db /var/lib/classctl/node/power.sqlite`. Заранее создайте этот каталог с владельцем root и правами `0700`. Синхронизируйте часы учительского и ученических ПК. В политике кабинета добавьте `system.power` к правам `teachers.local`. Например, `"rooms":{"lab-a":["view","control","system.power"]}`. При [установке через SSH](ssh/README.md) каталог и параметр службы добавляет установщик. Право задаётся в `rights` инвентаря.

Кнопки «Выключить все» и «Перезагрузить все» действуют на все доступные ПК аудитории, включая скрытые фильтром. При закрытом сайдбаре эти команды доступны по значкам под номером аудитории в полоске слева от грида. Чтобы выбрать отдельные ПК, отмечайте карточки Ctrl+кликом. Повторный Ctrl+клик снимает отметку. Щёлкните правой кнопкой по любой выбранной карточке для действия на всю выделенную группу. Правый клик по невыбранной карточке открывает действия для неё одной. Для работы с клавиатуры используйте Ctrl+пробел и Shift+F10 на карточке.

Подтвердите список ПК или число доступных ПК для команды всей аудитории. Команды работают до входа ученика. Если подтверждение от системы потеряно, проверьте состояние места перед повторной попыткой. Запрос и исход по каждому месту записываются в таблицу `audit` координатора под общим идентификатором.

Кнопка «Выключить без графической сессии» доступна в боковой панели и по значку монитора в левой полоске. Она выбирает доступные ПК без графической сессии во всей аудитории, включая скрытые карточки. Перед отправкой координатор повторно проверяет последнее полученное состояние каждого подтверждённого ПК. Если координатор уже получил сообщение о входе пользователя, портал показывает, что на этом ПК есть графическая сессия.

На изолированном Calculate Linux/OpenRC проверьте, что после перезагрузки выбранное место возвращается в сеть, а после выключения переходит в состояние «ПК вне сети». Сверьте журнал и убедитесь, что соседнее место остаётся доступным. `python3 server/power_acceptance.py` проверяет портал и доставку команды с подменой вызова login1.
