# Установка в одну аудиторию по SSH

Запускайте из корня рабочей копии на компьютере администратора. Нужны Python 3.10+, git, OpenSSH и OpenSSL. Цели должны быть явно записаны в known_hosts, доступны по ключу как root. SSH-адрес без имени пользователя означает root. Если в адресе явно указана другая административная учётная запись, скрипт использует sudo без пароля. Понадобятся настроенные DNS и сеть: узлам нужен адрес координатора на TCP-порту из инвентаря, для WebRTC нужен маршрут ICE. Реализация рассчитана на прямую связь в LAN.

1. Скопируйте пример и замените адреса SSH, DNS или IPv4 координатора, идентификаторы мест. SSH-алиасы могут задавать нестандартный порт. При первой установке список students задаёт порядок мест в одном ряду. Для каждого места достаточно ssh и node. Поле user в старых файлах игнорируется. SSH-доступ нужен администратору. Укажите выделенный учительский ПК в coordinator. Права локального портала задаются в rights для всего кабинета: view или view и control. Поле port задаёт порт агентов, ui_port — порт браузера на 127.0.0.1.
2. Проверьте инвентарь и выполните установку.

```sh
cp ops/ssh/inventory.example.json /tmp/classctl-room.json
# Отредактируйте /tmp/classctl-room.json перед выполнением команд ниже.
python3 ops/ssh/deploy.py --check /tmp/classctl-room.json
python3 ops/ssh/deploy.py /tmp/classctl-room.json
```

Код служб берётся из HEAD локального Git. Для доставки новых изменений служб сначала зафиксируйте их. Координатор и узлы клонируют локально переданный bundle. Установщик проверяет системные зависимости и подбирает окружение по содержимому `ops/requirements-live.txt`, включённых файлов и версии Python на узле. При первой подготовке такого окружения он вызывает pip. При обновлении только кода он подключает готовое окружение. После перехода со старого установщика этот кэш заполняется один раз на каждом ПК.

Если узлы выходят к индексу пакетов через прокси, задайте в JSON инвентаря `"pip_proxy": "http://proxy.school.lan:3128"`. Поддерживаются HTTP и HTTPS. При отсутствии поля или значении `null` pip использует настройки узла. Адрес прокси должен быть доступен с учительского и ученических ПК. Прокси и зеркало используются, когда нужно подготовить новое окружение.

Для внутреннего зеркала или репозитория PyPI задайте `"pip_index_url": "https://packages.school.lan/repository/pypi/simple/"` с фактическим адресом API Simple. Если до зеркала есть прямой доступ с узлов, оставьте `pip_proxy` равным `null` и используйте стандартные сетевые настройки узлов. Оба поля можно заполнить, если доступ к индексу требует отдельного HTTP-прокси. Для HTTP-индекса установщик добавляет его хост и указанный порт в PIP_TRUSTED_HOST только на время установки. Укажите адрес доверенного зеркала, если оно доступно по HTTP.

До запуска подготовьте Git, OpenSSL, системные сертификаты CA, Python с модулем venv и ensurepip (рекомендуется 3.12), а также OpenRC или systemd. На ученических ПК нужны KDE/X11, elogind или systemd-logind с busctl, xrandr, xkbcomp и поддержка XCB для Pillow. На учительском ПК нужен curl для проверки портала. Для работы с порталом используйте установленный Chromium.

Храните каталог CA (по умолчанию ~/.local/state/classctl) с правами 0700, сделайте защищённую резервную копию. Используйте отдельный --state для каждой аудитории. Повторный запуск использует ключи узлов и сертификаты с остатком срока более 30 дней. Обновление перезапускает службы. Чтобы добавить ПК, оставьте прежние записи в students и добавьте записи новых узлов. Скрипт допишет места в конец первого ряда. Существующие места и журнал SQLite сохраняются даже при перестановке записей в students. Если из списка пропал ранее развёрнутый nodeId или изменилась аудитория, скрипт остановится перед заменой политики. Назначения в policy.json целиком определяет текущий инвентарь. Не управляйте теми же файлами одновременно из Puppet или другого рабочего места.

Перед установкой скрипт сверяет `room` с идентификатором аудитории в SQLite координатора. При ошибке `existing room is …, requested …` проверьте `coordinator` и `room` в инвентаре. Для обновления существующей аудитории укажите её прежний идентификатор и каталог `--state`. Для другого кабинета укажите его учительский ПК и отдельный каталог `--state`.

На OpenRC установщик добавляет `classctl-server` на учительском ПК и `classctl-node` на обновляемых ученических ПК в уровень запуска `default` и проверяет их состояние после перезапуска. Итоговая проверка запрашивает главную страницу портала и `/state` на loopback учительского ПК и ждёт online обновлённых узлов.

Системный автозапуск действует для всех пользователей ученического ПК. При первой установке или переходе со старого автозапуска агент запускается при следующем входе в KDE/X11. При дальнейших обновлениях агент переключается на новую ревизию внутри того же сеанса. Преподавателю нужно заново открыть крупный просмотр, если он был открыт во время обновления.

Служба принимает процесс активной локальной сессии seat0, если login1 связывает с ней его PID. При запуске Plasma через пользовательский systemd проверьте эту привязку. Если systemd запускает автозапуск вне scope графической сессии, используйте классический запуск Plasma (systemdBoot=false в группе General файла startkderc). При обновлении скрипт убирает прежний пользовательский classctl.desktop, если его содержимое совпадает с созданным установщиком. Изменённая пользователем запись сохраняется и может перекрыть системную.

После установки войдите в KDE/X11 на одном месте и откройте выведенный локальный HTTP-адрес в Chromium учительского ПК. Сверьте изображения обоих мониторов, права кабинета и исчезновение изображения при выходе ученика. Подробности [физической приёмки](../live.md).

## Nextcloud «Внешние сайты»

Добавьте в корень JSON-инвентаря кабинета `"nextcloud_origin": "https://cloud.school.lan"` и повторите развёртывание. Укажите схему, имя хоста и порт, если он отличается от стандартного. Если Nextcloud открыт по адресу `https://cloud.school.lan/nextcloud`, укажите только `https://cloud.school.lan`. При отсутствии поля или значении `null` портал запрещает встраивание.

В Nextcloud добавьте внешний сайт с адресом `http://127.0.0.1:8768/`, подставив порт из `ui_port`. Оставьте «Перенаправление» выключенным и откройте сайт в Chromium на учительском ПК. Приложение «Внешние сайты» добавляет разрешение на полноэкранный режим в iframe. Щелчок по миниатюре открывает монитор во весь экран.

Chromium считает HTTP на `127.0.0.1` доверенным локальным адресом для проверки mixed content. Браузер обращается к порталу на учительском ПК. Фактический доступ к loopback зависит от политик браузера и заголовков Nextcloud. Проверьте открытие портала и полноэкранный просмотр на учительском ПК после установки.

Для выключения и перезагрузки из портала добавьте `system.power` в массив `rights` вместе с `view`. Право `control` можно указать отдельно. Установщик передаёт права координатору и настраивает журнал действий узла в `/var/lib/classctl/node/power.sqlite`.

## Тестовое обновление части класса

Оставьте полный список узлов в JSON и укажите ID тестовых ПК через `--only-node`. Координатор обновится и применит права из инвентаря. Установщик подключится по SSH только к координатору и выбранным ПК.

```sh
python3 ops/ssh/deploy.py classctl-room.json --only-node 01 --only-node 02
```

Для выборочного обновления используйте существующий каталог CA и прежние адрес и порт агентов. Координатор перезапустится, поэтому остальные узлы на короткое время переподключатся. Их сертификаты остаются действующими. Для полной поставки запустите ту же команду без `--only-node`.
