# Установка в одну аудиторию по SSH

Запускайте из корня рабочей копии на компьютере администратора. Нужны Python 3.10+, git, OpenSSH и OpenSSL. Цели должны быть явно записаны в known_hosts, доступны по ключу как root. SSH-адрес без имени пользователя означает root. Если в адресе явно указана другая административная учётная запись, скрипт использует sudo без пароля. Понадобятся настроенные DNS и сеть: узлам нужен адрес координатора на TCP-порту из инвентаря, для WebRTC нужен маршрут ICE. Реализация рассчитана на прямую связь в LAN.

1. Скопируйте пример и замените адреса SSH, DNS или IPv4 координатора, идентификаторы мест. SSH-алиасы могут задавать нестандартный порт. При первой установке список students задаёт порядок мест в одном ряду. Для каждого места достаточно ssh и node. Поле user в старых файлах игнорируется. SSH-доступ нужен администратору. Укажите выделенный учительский ПК в coordinator. Права локального портала задаются в rights для всего кабинета: view или view и control. Поле port задаёт порт агентов, ui_port — порт браузера на 127.0.0.1.
2. Проверьте инвентарь и выполните установку.

```sh
cp ops/ssh/inventory.example.json /tmp/classctl-room.json
# Отредактируйте /tmp/classctl-room.json перед выполнением команд ниже.
python3 ops/ssh/deploy.py --check /tmp/classctl-room.json
python3 ops/ssh/deploy.py /tmp/classctl-room.json
```

Код служб берётся из HEAD локального Git. Для доставки новых изменений служб сначала зафиксируйте их. Координатор и узлы клонируют локально переданный bundle. Установщик проверяет системные зависимости, а затем устанавливает Python-модули из `ops/requirements-live.txt` через pip в окружение конкретной ревизии.

До запуска подготовьте Git, OpenSSL, системные сертификаты CA, Python с модулем venv и ensurepip (рекомендуется 3.12), а также OpenRC или systemd. На ученических ПК нужны KDE/X11, elogind или systemd-logind с busctl, xrandr, xkbcomp и поддержка XCB для Pillow. На учительском ПК нужен curl для проверки портала. Для работы с порталом используйте установленный Chromium.

Храните каталог CA (по умолчанию ~/.local/state/classctl) с правами 0700, сделайте защищённую резервную копию. Используйте отдельный --state для каждой аудитории. Повторный запуск использует ключи узлов и сертификаты с остатком срока более 30 дней. Обновление перезапускает службы. Чтобы добавить ПК, оставьте прежние записи в students и добавьте записи новых узлов. Скрипт допишет места в конец первого ряда. Существующие места и журнал SQLite сохраняются даже при перестановке записей в students. Если из списка пропал ранее развёрнутый nodeId или изменилась аудитория, скрипт остановится перед заменой политики. Назначения в policy.json целиком определяет текущий инвентарь. Не управляйте теми же файлами одновременно из Puppet или другого рабочего места.

Скрипт проверяет /state на loopback учительского ПК и ждёт online всех перечисленных узлов. Системный автозапуск KDE действует для всех пользователей ученического ПК при следующем входе в X11. Вошедшему ученику нужно выйти и войти снова. Служба принимает процесс активной локальной сессии seat0, если login1 связывает с ней его PID. При запуске Plasma через пользовательский systemd проверьте эту привязку. Если systemd запускает автозапуск вне scope графической сессии, используйте классический запуск Plasma (systemdBoot=false в группе General файла startkderc). При обновлении скрипт убирает прежний пользовательский classctl.desktop, если его содержимое совпадает с созданным установщиком. Изменённая пользователем запись сохраняется и может перекрыть системную.

После установки войдите в KDE/X11 на одном месте и откройте выведенный локальный HTTP-адрес в Chromium учительского ПК. Сверьте изображения обоих мониторов, права кабинета и исчезновение изображения при выходе ученика. Подробности [физической приёмки](../live.md).
