# Миниатюры preview.v1 для T05

[Схема управляющих сообщений миниатюр](../preview-v1.schema.json) и [последовательность для DP-2](sequence.json) дополняют [контракт состояния](../README.md). При локальной загрузке схем сопоставить urn:classctl:control:v1 файлу contracts/v1.schema.json. Подписка охватывает один видимый выход. Для двух мониторов открыть две подписки поверх одного WSS.

## Совместимость при развёртывании

| Управление | Источник и координатор | Координатор и браузер | Результат |
|---|---|---|---|
| v1 | feature preview.jpeg.v1 | WebSocket subprotocol classctl.preview.v1 | JPEG-превью |
| v1 | Только прежняя feature preview | Любой клиент | Инвентарь и состояние доступны, превью недоступно |
| v1 | preview.jpeg.v1 | Нет общего subprotocol | Отказ открытия WSS миниатюр, статус доступен |
| Нет общей версии управления | Любая комбинация | Любая комбинация | Остановить обмен до подписки |

Сначала обновить координатор с поддержкой опционального канала, затем источник и браузер. После отката любого участника повторить согласование. Первый потребитель — интеграция T05. T01 читает локальные фикстуры, T02 моделирует статус, T03 остаётся измерительным стендом.

## Порядок и формат

1. Браузер выбирает monitorId из свежего status и отправляет JSON subscribe с новым subscriptionId, уникальным в соединении. Координатор проверяет право просмотра аудитории, привязку узла, сессию, ревизию, доступность выхода и feature. Затем открывает подписку вверх по доверенному каналу узла; источник подтверждает ready. Только после этого координатор посылает ready браузеру. При отказе или отмене координатор посылает unsubscribe с той же привязкой. Отзыв права немедленно закрывает подписку.
2. Управляющие сообщения передаются отдельными текстовыми сообщениями WebSocket в UTF-8. Один кадр занимает одно бинарное сообщение: четыре байта беззнаковой длины заголовка в сетевом порядке, затем JSON preview.frame в UTF-8, затем ровно byteLength байт JPEG. Заголовок от 1 до 4096 байт, JPEG до 1 МиБ. Обе стороны проверяют границы, версию, тип, схему и привязку до декодирования. Ошибка формата или декодирования закрывает подписку и очищает кадр. На новом соединении требуется новая подписка.
3. Источник нумерует кадры возрастающим seq от 1 в пределах подписки. capturedAt — время захвата на источнике. Для каждой пары подписчик/выход отправитель держит один кадр в ожидании ACK и один ожидающий отправки, заменяемый более новым. Координатор подтверждает источнику принятие в свой ограниченный буфер; браузер подтверждает координатору успешную отрисовку. ACK освобождает только точный отправленный seq в той же привязке. При отсутствии ACK по локальному таймауту завершить подписку. Для нескольких браузеров координатор может разделять одну верхнюю подписку и ведёт соответствие идентификаторов и seq на каждом участке.
4. После успешной повторной проверки неизменного выхода источник отправляет verified с seq исходного кадра и временем проверки. Обновлять свежесть можно только для текущего показанного seq и более нового verifiedAt. Истечение таймаута измеряется монотонными часами получателя. Начальный кадр нужен даже для статичного экрана. Heartbeat узла учитывается отдельно. Таймауты настраиваются для сети учреждения.
5. При скрытии карточки браузер посылает unsubscribe. Обе стороны освобождают очереди, таймеры и незавершённое декодирование. При logout, offline, смене ревизии, узла, монитора, подписки или отзыве права синхронно очистить изображение. Проверить актуальность также после асинхронного декодирования непосредственно перед отрисовкой. Кадры и подтверждения от прежней привязки отбрасываются. При повторном открытии начать с нового полного JPEG.

[Эталонный получатель](receiver.mjs) принимает структурно проверенные сообщения. T05 подключает его к статусу и обработчикам canvas, WSS и декодера. Общая проверка требует Node.js 18+ и выполняет сценарий смены сессии и ревизии с декодированием в полёте.
