# Контракты v1

[JSON Schema Draft 2020-12](v1.schema.json) — общий источник формы управляющих сообщений. Верхний уровень выбирает тип по kind, общие структуры собраны в $defs. Время передаётся в RFC 3339 со смещением. Геометрия измеряется в пикселях корневого окна X11.

| Тип | Эталон | Обязанность потребителя |
|---|---|---|
| room | [Аудитория](examples/room.json) | Сохранять seatId, row и column независимо от состояния ПК. Пустая привязка допускает null. Ячейки и привязанные узлы уникальны в аудитории |
| status | [Два выхода](examples/status.json) | Раздельно учитывать availability, session и preview. monitorId уникален внутри сессии. После переподключения выхода увеличивать layoutRevision |
| access | [Просмотр второго выхода](examples/access.json) | Проверять текущие привязку, права, sessionId, layoutRevision и наличие monitorId. Для общего рабочего стола передавать target со scope=desktop |
| capabilities | [Объявление](examples/capabilities.json) | Пересобирать список при новом соединении и смене сессии. Отображать только известные и разрешённые действия |
| action.request | [Запрос](examples/request.json) | Фиксировать список узлов, проверять параметры по доверенной схеме действия, положительный TTL и верхний предел |
| action.result | [Частичный успех](examples/result.json) | Сопоставлять requestId, требовать ровно один исход на каждую цель в снимке операции |

**Свежесть.** lastFrameAt — время исходного кадра, lastVerifiedAt — время последней успешной проверки захвата той же сессии. Для карточки с несколькими выходами берётся наихудшая свежесть из подписанных выходов. pending означает ожидание первого кадра. moving и unchanged требуют кадр и подтверждение источника. При неизменном столе процесс продолжает подтверждать состояние каждого выхода даже при подавлении кадров. Обычный heartbeat ПК не продлевает свежесть изображения. При просрочке подтверждения сервер переводит превью в stale, при просрочке heartbeat отдельно меняет availability. Отсчёт таймаутов ведётся по монотонному времени получения подтверждения. Пороги проверяет [T03](../tasks/T03.md). При смене пользователя очистить старый кадр.

**Совместимость.** v1 закрывает набор полей. Новые значения в открытом списке features допускаются, незнакомая возможность игнорируется. Неизвестный actionId недоступен для исполнения. Для смены формы сообщения добавить соседнюю схему версии, согласовать пересечение поддерживаемых версий до обмена и проверить смешанное развёртывание. При отсутствии общей версии завершить обмен с диагностикой. Новые доверенные действия с прежней формой объявления допускаются в v1.

[Offline с сессией](invalid/offline-session.json), [монитор без ID](invalid/missing-monitor.json) и [повтор цели](invalid/duplicate-target.json) обязаны получить отказ. Полномочия, актуальность и связь с текущим состоянием проверяет исполнитель после структурной валидации.

Для подписки на выход и передачи JPEG в T05 используйте [контракт preview.v1](preview/README.md).

Возможность `session.identity.v1` позволяет координатору запросить метаданные активной сессии через `describe`. [Схема ответа](session-identity-v1.schema.json) допускает необязательное поле `displayName` с полным именем из GECOS. Поле `user` сохраняет прежнее значение для совместимости со старыми источниками. Портал использует `displayName` для подписи пользователя и `room.seats[].nodeId` для подписи компьютера.
