# T20. Установка и обновление через агенты Puppet

Администратор назначает роли преподавателя и ученика. Каждый агент устанавливает текущую ревизию выбранной ветки при очередном применении каталога. Выключенный ПК догоняет класс самостоятельно. Владелец манифестов — ops. Координатор и узел используют существующие форматы аудитории, прав и сертификатов. Переход с SSH сохраняет ключи, номера мест и базы данных.

Приёмка на пилотной паре по [инструкции](../ops/puppet/README.md): первое применение, повтор без перезапуска, новая ревизия при выключенном ученическом ПК и его возвращение в сеть. Проверить повтор после неудачной установки и вход в KDE. Запустить также `python3 checks/verify.py`.

Локальная проверка: `puppet parser validate ops/puppet/classctl/manifests/*.pp` и `python3 ops/puppet/test_update.py`. Тест использует временную ветку Git и отдельные каталоги двух машин. Системный установщик подменён для проверки повторного применения и восстановления после сбоя без запуска системных служб.
